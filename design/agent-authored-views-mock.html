Agent-authored views — a reusable UI layer in the chat

Every agent skill can render an interactive view inline in the chat. The agent picks the best-fitting view for the skill + project from a shared Views library. If none fits, it writes a new view (sandboxed), renders it live, and saves it to the library — so next time that skill (or a similar one) reuses it. You interact with the view; the controls call back to the agent like tools.

How it works

  • A skill can declare a viewHint; otherwise the agent matches the best view by skill + project intent.
  • Views render in a sandbox and talk to the agent through a small contract (emit events / call tools) — safe, not arbitrary access.
  • No match → the agent writes a view to that contract, it renders, and is saved + versioned in the library.
  • Reuse is smart: the same view serves related skills across projects; you can edit or fork it.

Engineering reality (flagged early): letting the agent author + persist + render UI needs a safe runtime (sandboxed render, no raw DOM/network — a fixed component contract), a views registry (name, code, version, skill/project match, usage), and a skill→view resolver. That's a real platform build — this mock is to align on the shape first. We'd start with a small set of curated library views (film/leads/design/campaign) + the resolver, then add the generative path behind the same contract.
